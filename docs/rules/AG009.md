# AG009: non-idempotent-tool-with-retry

## What it detects

Likely payment, deletion, write, email, or send tools invoked from retryable
loops without a visible idempotency guard.

## Why it matters

A retry may duplicate an irreversible side effect.

## Bad example

```python
while True:
    send_email_tool(message)
```

## Good example

```python
send_email_tool(message, idempotency_key=request_id)
```

## How to fix

Use provider idempotency keys, transaction state, or a tool designed to be
safe when repeated.

## How to suppress

Use inline AG009 suppression when the tool contract guarantees idempotency.
