# AG001: unbounded-retries

## What it detects

AG001 detects retry and loop constructs around LLM, HTTP, or tool calls when no
maximum attempt count or time budget can be established. It covers unbounded
`while` retry loops, retry decorators and calls from common retry libraries,
retry recursion, and literal `max_retries` values greater than 10.

## Why it matters

A persistent provider failure can make an agent loop forever, spend unlimited
tokens, or continuously hammer a degraded service. Backoff alone does not
bound the total cost or duration.

## Bad example

```python
import requests


def fetch():
    while True:
        try:
            return requests.get("https://example.com")
        except OSError:
            continue
```

## Good example

```python
import requests


def fetch():
    for attempt in range(3):
        try:
            return requests.get("https://example.com", timeout=10)
        except OSError:
            if attempt == 2:
                raise
    raise AssertionError("unreachable")
```

With Tenacity, use a bounded stop policy such as
`stop_after_attempt(3) | stop_after_delay(30)` and an appropriate exponential
backoff with jitter.

## How to fix

Add a counter, deadline, or library stop policy. Keep the total retry window
short enough for the agent's overall run budget, and use backoff with jitter to
avoid synchronized retries.

## How to suppress

Suppress one finding on its line when the bound is enforced by a verified
external policy:

```python
while True:  # agentguard: ignore[AG001] reason: gateway enforces a run deadline
    poll_gateway()
```

For a file-level exception, put this directive within the first ten lines:

```python
# agentguard: ignore-file[AG001] reason: bounded by the worker supervisor
```
